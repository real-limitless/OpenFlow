## Credentials

The node connects to an MQTT broker using `mqtt` credentials with these fields:

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| protocol | enum | `mqtt` | One of `mqtt`, `mqtts`, `ws` |
| host | string | (none) | Broker hostname or IP |
| port | number | 1883 | Broker port |
| username | string | (none) | Optional auth |
| password | string | (none) | Optional auth |
| clean | boolean | true | Clean session flag |
| clientId | string | (autogenerated) | Custom client identifier (supports expressions) |
| ssl | boolean | false | Enable TLS |
| passwordless | boolean | true | SASL EXTERNAL cert auth (when ssl=true) |
| ca | string | (none) | CA certificates (when ssl=true) |
| rejectUnauthorized | boolean | false | Validate server cert (when ssl=true + passwordless=true) |
| cert | string | (none) | Client certificate (when ssl=true + passwordless=true) |
| key | string | (none) | Client key (when ssl=true + passwordless=true) |

A credential test (`mqttConnectionTest`) validates connectivity before execution by attempting a broker connection.

## Parameters

| name | type | default | required | displayOptions | notes |
|------|------|---------|----------|----------------|-------|
| topic | string | (none) | yes | always | MQTT topic to publish to |
| sendInputData | boolean | true | no | always | When true, serializes incoming item JSON as the message payload |
| message | string | (none) | conditional | shown when `sendInputData` is false | Custom message text |
| options.qos | number | 0 | no | always | MQTT QoS level: 0 (at most once), 1 (at least once), 2 (exactly once) |
| options.retain | boolean | false | no | always | Whether the broker retains the last message on this topic |

## Runtime behavior

### Input

Each item from `main` input is processed independently. Items carry data to be published or metadata for expression resolution.

### Output

The node publishes one MQTT message per input item to the configured broker. After all publishes complete, it waits for in-flight acknowledgments (required for QoS 1/2) and returns the original input items unmodified on output[0]. Output is built per-item: each input item produces exactly one output item in the same order. No new keys are added to items on success.

### Errors

- Credential validation runs a broker connection test (`mqttConnectionTest`): if the client cannot connect, the credential test returns an error.
- Publish failures (connection refused, invalid topic, broker timeout) propagate as execution errors.
- `continueOnFail` is respected: when enabled, a failed item produces an error item — `{ json: { ...item.json, error: <error message> }, pairedItem: { item: <index> } }` — on the output instead of halting. Non-failed items still pass through as identity. Output length equals input length.

### Expressions

`topic`, `message`, and `clientId` (credential) accept expression strings.

## Acceptance tests

### Test: publish static message

**Given** input items:

```json
[{ "json": {} }]
```

**Parameters:**

```json
{
  "topic": "sensors/temperature",
  "sendInputData": false,
  "message": "22.5",
  "options": { "qos": 1, "retain": false }
}
```

**Expect** output[0] to equal the input items (identity passthrough). The executor must have attempted a publish with topic `sensors/temperature`, payload `"22.5"`, QoS 1.

### Test: publish input data as JSON

**Given** input items:

```json
[{ "json": { "device": "thermo-01", "temp": 22.5 } }]
```

**Parameters:**

```json
{
  "topic": "sensors/temperature",
  "sendInputData": true
}
```

**Expect** output[0] to equal the input items. The published payload must be the JSON stringified version of the input JSON (`{"device":"thermo-01","temp":22.5}`).

### Test: expression topic

**Given** input items:

```json
[{ "json": { "device": "sensor-01" } }]
```

**Parameters:**

```json
{
  "topic": "={{ $json.device }}/reading"
}
```

**Expect** the topic resolved to `sensor-01/reading` for the publish call. Output[0] equals input items.

### Test: QoS and retain flags

**Given** input items:

```json
[{ "json": {} }]
```

**Parameters:**

```json
{
  "topic": "test/retain",
  "sendInputData": false,
  "message": "hello",
  "options": { "qos": 2, "retain": true }
}
```

**Expect** publish executed with QoS 2 and retain=true. Output[0] equals input items.

### Test: publish failure with continueOnFail

**Given** input items:

```json
[{ "json": { "id": 1 } }, { "json": { "id": 2 } }]
```

**Parameters:**

```json
{
  "topic": "test/error",
  "sendInputData": false,
  "message": "fail",
  "continueOnFail": true
}
```

**And** a broker that rejects the publish (e.g. connection refused).

**Expect** output[0] to contain two items: the first is `{ json: { ...item.json, error: <error message>, pairedItem: { item: 0 } } }` and the second is identity passthrough of the second input item (or both error items depending on which publish fails). The node does not throw; it returns all items with error metadata on failed ones.

### Test: credential failure

**Given** invalid broker credentials (e.g. unreachable host).

**Expect** the node to throw an execution error. No items produced on output[0].
