# Installation

This branch (`CORE`) is **documentation only**. There is no app and no Compose file here.

To **install and run OpenFlow**, check out a **product branch**, then run the stack **only in containers** (Docker Compose, Podman Compose, or the one-line installer).

**Host Node/npm is not a supported runtime** for the application. Do not use `npm run dev` (or similar) on the host as the product server.

## 1. Clone and switch to a product branch

```sh
git clone https://github.com/real-limitless/OpenFlow.git
cd OpenFlow

# Active development line
git checkout DEVELOPMENT

# Or the default product branch:
# git checkout main
```

After switching you should see `docker-compose.yml`, `Dockerfile`, `src/`, etc.

If you only see markdown files (this `CORE` layout), you are still on docs-only:

```sh
git checkout DEVELOPMENT
```

## 2. Prerequisites

| Required | Notes |
| --- | --- |
| **Container engine** | Docker Engine **or** Podman (or equivalent) |
| **Compose** | `docker compose` / `podman compose` / `docker-compose` / `podman-compose` |

You do **not** need Node.js on the host to **run** OpenFlow. Node is used **inside** the image build.

---

## 3. Run with Compose (recommended)

```sh
# Docker
docker compose up -d --build

# Podman (when compose is available)
podman compose up -d --build
# or: podman-compose up -d --build
```

Open **http://localhost:3000**

First boot builds the image, starts Postgres + Redis + API, runs migrations, and can generate a credentials key if unset.

```sh
docker compose logs -f api    # or: podman compose logs -f api
docker compose down           # stop (volumes keep data)
```

Optional env:

```sh
cp .env.example .env
# edit CREDENTIALS_KEY, AUTH_DISABLED, assistant keys, etc.
docker compose up -d
```

### Interactive host helper (optional)

On a product branch, a bash TUI can orchestrate **containers only**:

```sh
bash scripts/tui.sh
```

The TUI must not be used to start a host Node app — only Compose start/stop/logs/setup.

Non-interactive container setup (when present on the product branch):

```sh
bash scripts/setup.sh
```

## 4. One-line install (prebuilt image)

Preferred interactive installer (product branch `main`):

```sh
curl -fsSL https://raw.githubusercontent.com/real-limitless/OpenFlow/main/scripts/get-openflow.sh | bash
```

Non-interactive examples:

```sh
# try-out
curl -fsSL https://raw.githubusercontent.com/real-limitless/OpenFlow/main/scripts/get-openflow.sh | bash -s -- --yes

# production-oriented
curl -fsSL https://raw.githubusercontent.com/real-limitless/OpenFlow/main/scripts/get-openflow.sh | bash -s -- --yes --mode production
```

Back-compat wrapper (always non-interactive `--yes`):

```sh
curl -fsSL https://raw.githubusercontent.com/real-limitless/OpenFlow/main/scripts/install.sh | bash
```

Writes Compose + `.env` under `~/openflow` by default (override with `OPENFLOW_HOME`) and starts the stack. **Containers only.**

If a GHCR image is not published yet, use a clone + `docker compose up -d --build` instead.

## 5. Production-oriented stack

On a product branch, with a strong `CREDENTIALS_KEY` in `.env`:

```sh
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

Turns auth on by default, disables hot-reload, binds DB/Redis more tightly. Put TLS (Caddy/nginx/Traefik) in front before public exposure.

Full checklist on the product branch:

- [docs/install.md](https://github.com/real-limitless/OpenFlow/blob/main/docs/install.md)
- [SECURITY.md](https://github.com/real-limitless/OpenFlow/blob/main/SECURITY.md)

## What is not supported

| Approach | Status |
| --- | --- |
| `docker compose` / `podman compose` | **Supported** |
| `scripts/get-openflow.sh` / `scripts/install.sh` (Compose stack) | **Supported** |
| Host `npm run dev` / host Node as the app | **Not supported** |
| Host-only Postgres without containers for “the app” | **Not supported** (use full Compose stack) |
| Running OpenFlow from the `CORE` branch | **Not possible** (docs only) |

## Default ports (product stack)

| Service | Port |
| --- | --- |
| OpenFlow UI + API | 3000 |
| PostgreSQL (published for local tools) | 15432 |
| Redis | 6379 |

Health (when the API container is up):

- `GET http://localhost:3000/health`
- `GET http://localhost:3000/health/ready`

### First-run notes

- **Auth is often off by default** for local try-out — fine on a private machine, **not** for the public internet.
- `CREDENTIALS_KEY` encrypts stored workflow credentials (generated by setup, TUI, or Docker entrypoint when unset).
- Local Compose DB defaults are for try-out only; do not expose them on the public internet.
